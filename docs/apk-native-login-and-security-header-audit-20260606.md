## 2. Current APK Login Architecture Before Patch
Before this patch, the Flutter APK did not use a native login as the first student login experience.

Observed source flow:
1. `main.dart` rendered `SplashPage`.
2. After server connection, `AppRouter` opened `ExamPage` directly.
3. `ApiService.getExamUrl()` returned `$_serverUrl/student/`.
4. `ExamPage` rendered that URL inside `InAppWebView`.
5. `/student/` rendered `templates/student/index.html`, the web `Portal Siswa` login.

Conclusion: the current APK was effectively using **WebView login**, not native login.

## 3. Reason UI Changed From Old Blue Login to Portal Card
The old blue login UX was bypassed because the app router opened the WebView immediately after splash.

Also, `flutter_client_code/lib/pages/login_page.dart` was no longer a login screen; it had become a safe landing page titled `Sesi Ujian Berakhir` used after logout/force-kick/emergency exit.

Before patch:
- Old native login screen in active route: **NO**.
- `LoginPage` was an end-session page: **YES**.
- `main.dart` bypassed native login and opened WebView: **YES**.

## 4. Exact Source of “Security Headers Missing”
The Indonesian warning is generated by backend auth enforcement:

- `app/api/auth.py` → `_enforce_student_mobile_signature()`:
  - Missing `X-App-Signature` or `X-App-Timestamp` raises:
    `Security Headers Missing. Update aplikasi ujian Anda.`

A related English message exists in:
- `app/middleware/sxb_enforcer.py` for strict API paths.

The WebView login page at `templates/student/index.html` posted login through `fetch()` with only:

```js
headers: { 'Content-Type': 'application/json' }
```

That request did not use `static/js/api.js` / `api.getHeaders()`, so it did not reliably send:
- `X-Build-Token`,
- `X-App-Signature`,
- `X-App-Timestamp`.

The previous WebView injection fix seeded `localStorage.sxb_build_token` and `localStorage.sxb_app_signature`, but the web login fetch path still did not read those values for its direct login request.

## 5. Missing Field Assessment
Root missing fields for the red warning:
- `X-App-Signature`: missing from web login fetch.
- `X-App-Timestamp`: missing from web login fetch.

`localStorage.sxb_build_token` and `localStorage.sxb_app_signature` were already injected by the recent Flutter patch, but the web login page did not use them for its direct `fetch('/api/student/auth/login')` call.

## 6. Target Design Decision
Target design selected: **Native APK shell login first**.

Final source flow after patch:
1. Native splash.
2. Native blue login screen.
3. Native login calls backend via Dio `ApiService.login()`.
4. Dio interceptor supplies APK headers.
5. Token/user are stored securely.
6. WebView opens only after successful login.
7. WebView receives `access_token`, `user`, `sxb_build_token`, and `sxb_app_signature` at document start.
8. Autosave/final-submit WebView runtime remains unchanged.

## 10. Build Token Policy
Before patch, `flutter_client_code/lib/config.dart` in Git contained a full generated `BUILD-*` token.

After patch:
- `config.dart` in Git is a template only.
- It contains no production generated build token.
- Release builds must be generated with APK Builder/build process, which overwrites `config.dart` locally.
- Generated full tokens must not be committed.
- Reports/logs should use masked format only, for example `BUILD-2026...2ZVKC7`.
